## Professional distinction

Node 01 determines whether the underlying story, premise, character engine and conflict system are worth developing. Node 02 turns the approved story design into a functioning dramatic text. The workflow must preserve this boundary while allowing screenplay diagnosis to send root-cause problems back to story development.

## Source-grounded mechanisms

### 1. Stage the work; do not draft before the design is sufficiently understood

The inspected screenwriting workflow separates premise/theme, structure, character/conflict, scene list, draft, revision and submission. Each stage has distinct deliverables and advisory exit checks. It also allows rollback when a later stage exposes an upstream problem.

**Application**
- Node 01 outputs premise, theme/control idea, story engine, protagonist/opposition, causal conflict network, stakes and a story viability assessment.
- Node 02 outputs dramatic structure, sequence/scene design, screenplay draft, revision records and format-compliant text.
- A screenplay problem is classified as text execution, scene design, structural design or root story design before routing rework.

### 2. Use multiple structural models as diagnostic lenses

The source places different story-structure models side by side and assigns them different explanatory functions. This supports a model-selection approach rather than enforcing one beat sheet on every project.

**Application**
- Choose structure by medium, genre, length, audience promise and intended experience.
- Treat page positions and beat counts as hypotheses to test, not universal acceptance criteria.
- Record why a model was selected and what it cannot explain about the project.

### 3. Treat scenes as value-changing dramatic units

The inspected scene-craft Skill defines a scene through conflict and a meaningful change in a value-bearing situation. It analyzes objectives, tactics, beats, subtext, turning points, pacing, props and entrances/exits.

**Application**
For each major scene, record:
- whose scene it is;
- immediate objective;
- obstacle/opposing force;
- stakes and cost of failure;
- tactic and counter-tactic;
- information asymmetry;
- opening and closing value state;
- irreversible or consequential change;
- scene function in the larger sequence.

A scene with no meaningful change should be challenged, but not automatically deleted: it may establish atmosphere, contrast, rhythm, character observation or delayed payoff. The responsible writer must explain its function.

### 4. Preserve project state without turning the Story Bible into the whole project

The source workflow stores decisions, current stage and next action in a compact Story Bible, while keeping outlines, treatments and screenplay drafts as separate artifacts. Decision changes are logged.

**Application**
The Hub's future project protocol should separate:
- compact canonical project state;
- full creative artifacts;
- decision and change history;
- open questions and unresolved disagreements;
- source evidence and version references.

The Story Bible is a navigation and continuity index, not a substitute for the screenplay or full project records.

## Inputs and outputs

**Inputs**
- creative premise and intent;
- target medium, format, runtime and audience;
- approved story development findings;
- constraints, reference works and rights context.

**Outputs**
- story-design package from node 01;
- screenplay architecture and scene/sequence plan from node 02;
- screenplay drafts and revision records;
- root-cause issue reports routed to node 01 where needed.

## Acceptance criteria

A workflow implementation should verify:
- each stage has an explicit deliverable and owner;
- stage completion is not inferred from prose volume;
- decisions persist across sessions with version references;
- structural model selection is justified;
- scene-level goals, obstacles and value changes are inspectable;
- revision findings are routed to the correct upstream owner;
- user approval is required for material changes to locked creative intent;
- the process does not force feature, series, short-form and stage projects into one route.

## Failure modes

| Failure | Diagnostic response |
|---|---|
| Drafting starts before premise/story engine is stable | Return to node 01; do not polish dialogue around a broken engine |
| One beat-sheet is imposed on every project | Re-evaluate model against medium, genre and audience promise |
| Scene is vivid but has no causal or dramatic function | Test objective, opposition, value change and sequence role |
| Scene is mechanically deleted because its value does not flip | Check whether it serves atmosphere, contrast, rhythm, observation or payoff |
| Story Bible grows into a duplicate screenplay | Keep only canonical decisions, state and artifact references |
| Later writing reveals upstream contradiction | Open a root-cause issue and route to node 01 |

## Limits

This entry synthesizes source mechanisms; it is not a universal screenwriting doctrine. Artistic judgment remains with the responsible creator and professional agents. The underlying upstream reference materials are not reproduced here.
